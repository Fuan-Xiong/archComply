# 答辩题库（2 分钟问答 · 队长主答，其他人补技术细节）

> 每题 = **结论先行一句话 + 一个证据 + 一个数字**。不要背长段，背骨架。
> 评委问技术细节 → 队长接一句"这块我们 B1/B2 讲"，**不要抢答，也不要冷场**。

## Q1 为什么要多 SubAgent，一个 Agent 干不了吗？（必问）

**答**：一个 Agent 做三件事会互相污染——计划、执行、校验混在一个上下文里，最后变成"自己判自己"。
我们拆成 **Planner / Executor / Verifier**：
- Planner 只产出「检查项 → 规则 → 取哪段原文」，不碰结论；
- Executor 每条规则一个子任务，**上下文隔离**，单条失败不拖垮全局；
- Verifier 只做一件事：**没有 blockId 证据就判 review**，有一票否决权。
一句话：**分工是为了"可追责"，不是为了炫技。**

> 如果追问"多 Agent 不是更贵吗" → 见 Q3。

## Q2 怎么防死循环？（必问）

**答**：四道闸，代码里都能 grep 到：
1. `maxRounds = 3`：Planner 最多重规划 3 次，超了降级出部分结果（`status: partial`）；
2. 单步 `timeout = 90s`，超时即中断该子任务；
3. 重试上限 1 次，**重试前必须换策略**（换切片/换提示），同参数重试直接禁止；
4. **无进展检测**：连续两轮不产生新的 `rule_result` 就终止。

补充：`req.on('close')` 一断就把 AbortSignal 传进 harness，**用户点中断能真停，不是假停**。

## Q3 怎么省 Token？（必问，B2 补）

**答**：三层削，砍掉的是最贵的部分：
1. **能代码判的不给模型**：8 条规则里 6 条是日期/比例/格式，确定性比对**零 Token**（演示数据里有 `deterministicCalls: 6`）；
2. **不传全文，只传切片**：按条款标题+关键词召回相关 block，单次上下文从整篇降到几百字；
3. **结果不重复序列化**：pass 规则不进 `issues` 数组，SSE 只推增量 `delta`。

数字：7600 Token / 20 秒出 8 条规则结论，其中 4 次 LLM 调用。

## Q4 怎么保证复跑一致？

**答**：同一输入 → 同一输出，靠三件事：
1. `temperature` 走环境变量，演示固定为低值；
2. **确定性规则优先**，结果不受模型波动影响的规则占多数；
3. `reviewId` + 规则清单版本号一起记录，**每次结果都能对账**；语义规则的 `confidence < 0.7` 直接进 `review`，不硬判。

主动补一句："我们不敢承诺 100% 一致——语义判断有波动，所以我们把不确定的显式标成 review，而不是假装确定。"（这句很加分）

## Q5 溯源怎么做到精准？（必问，B2 补）

**答**：解析层就给每个段落发身份证：`docId / page / blockId / charStart / charEnd`。
- 模型只被允许**返回规则相关的文本片段**，服务端用 `blockId` 反查原文，离线**回填精确偏移**；
- 回填失败 = 证据不成立 = 判 `review`，**绝不猜**；
- 前端拿 `blockId` 直接滚到 DOM 节点高亮，不靠关键词搜索定位（搜索会高亮错位置）。

## Q6 覆盖矩阵是干嘛的？（高光题，主动讲）

**答**：它是"**不漏查**"的保险。
每条规则有一个状态 `pending/done/review`，跑完还 pending 的规则**前端红字告警**。
我们宁可承认"这条没查到"，也不让系统输出一个看起来很完整的假报告。
（演示时故意留一条未覆盖，红色告警当场可见。）

## Q7 只用 120 分钟，怎么保证按时交？

**答**：靠三个纪律：
1. **契约先行**：14:10 前三份契约（规则清单 / 结果 Schema / SSE 协议）发群，三方并行不互相等；
2. **Mock 并行**：前端不等后端，用 Mock SSE 先跑通页面；B1 不等 B2，用假 skill 返回固定结果；
3. **硬节点 + 封版**：14:40 一条规则端到端，15:20 可演示，16:05 后只修 bug。

## Q8 如果规则文档变了怎么办？

**答**：规则清单是**外置配置**，不是写死在代码里。改 `rules清单.md` → B2 的 `loadRules` 重新加载 → 覆盖矩阵自动重算。加规则不改代码。

## Q9 为什么选 qwen code sdk？

**答**：它把 Agent 循环、工具调用、skill 加载都封好了，我们 120 分钟要的是**能跑通的链路**，不是从零造轮子。模型名、base_url、key 全走环境变量，换模型不改代码。

## Q10 这套东西真实场景能落地吗？

**答**：能，因为它的价值不在"比人聪明"，在"**比人稳定 + 可审计**"：同样的规则跑一万份文件结论口径一致，每条结论都能点回原文给法务看，未覆盖的会明确标出来。这正是审计/合规场景最需要的东西。
