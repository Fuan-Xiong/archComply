# 演示动线（3 分钟 · 逐秒脚本）

> 演练 2 遍以上，换人操作一次（防演示人手抖）。
> 顺序不能乱：**业务 → 交互 → 证据 → 规则 → 架构 → 指标 → 价值**。

## 0:00—0:20 队长开场（讲场景，不讲技术）

> "投标/合同评审里，最怕的不是查不出问题，而是**漏查**。人工看 20 页合同、8 条规则，一上午就没了，还容易漏。
> 我们做的是一个**Agent 协同的合规评审系统**：给定文档和规则清单，它自己规划检查项、逐条取证、给出可点击溯源的结论，并且**告诉你哪些规则没查**。"

要点：先立"漏查"这个痛点，后面的覆盖矩阵才有落点。

## 0:20—0:50 前端 F：跑起来

- 选择文档（`投标合同样本.pdf`）→ 点「开始评审」
- 展示：进度条、流式输出、thinking 置灰小字
- 一句话："**用户全程看得见它在干什么**，不是转圈等结果。"

## 0:50—1:20 前端 F：结果卡片 + 溯源（全场最高光）

- 切到结果区：2 红 1 黄 5 绿
- 点开 R001「报价有效期」卡片：结论 `fail`、严重级别 `high`、证据 `报价有效期：60 天`
- **点证据 → 原文滚动过去并高亮**
- 一句话："**每条结论都能点回原文，找不到证据的我们不下结论**。"

## 1:20—1:55 后端B：规则引擎 + Token 优化

- 覆盖矩阵：6 done / 1 review / **1 未覆盖（红色告警）**
- 讲："8 条规则里 6 条是确定性规则（日期、比例、格式），**代码比对、零 Token**；只有 2 条语义规则走大模型。所以 20 秒 7600 Token 出结果。"
- 讲："未覆盖会红，这样系统不会假装自己很懂。"

## 1:55—2:25 后端A：Agent 协同 + 防死循环

- 讲架构：Parser → Planner → Executor → Verifier，SubAgent 各管一段
- 讲防护：`maxRounds=3`、单步 `timeout=90s`、失败重试 1 次后降级 review、**连续无进展即终止**
- 讲："Verifier 卡证据：没 blockId 就打回，不进报告。"

## 2:25—2:50 队长收尾：指标 + 价值

- 指标面板：总 Token、总耗时、阶段耗时、问题数、覆盖率 87.5%
- 价值三句：① 不漏查（覆盖矩阵）② 可复核（溯源）③ 省成本（确定性规则优先）

## 2:50—3:00 留白

不要讲满 3 分钟。留 10 秒让评委提问，比挤满更有底气。

---

## 演示容错预案

| 故障 | 立即动作 |
|---|---|
| 模型超时/API 挂 | 切 **Mock 模式**（改 `VITE_API_BASE` 指向 `mock/sse-server.mjs`），全流程照常演示 |
| 网络断 | 播 **备用录屏**，人继续讲 |
| 页面白屏 | 刷新一次；第二次失败直接切录屏 |
| 流式中途卡住 | 点中断 → 演示"中断"这个功能本身（化事故为亮点） |
| 数据库/文件丢失 | 用提交包里的 `mock/fixtures` 数据 |
